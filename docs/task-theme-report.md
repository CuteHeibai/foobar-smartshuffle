# Chinese Verdant theme report

Implemented only `theme/verdant/`, `tests/theme_tests.js`, and this report. Vendored baseline copied from `vendor/verdant-foobar2000-theme-master/theme/verdant/`; MIT LICENSE and THIRD-PARTY-NOTICES preserved. Original author superziper remains credited in main.js.

## Delivered behavior

- Retained Spotify black/gray/green palette: #000000 canvas, #121212 panels, #181818 raised surfaces, #2A2A2A hover, #B3B3B3 secondary text, #1ED760 active/focus. Microsoft YaHei UI supplies Chinese text; MDL2 icons remain unchanged. Compact source/song headers and adaptive sidebar widths preserve space at 900×600. Main navigation, home, song/playlist/search, queue, empty states, editing menus and confirmations are Chinese.
- Added `data/smartshuffle.js`: UTF8 without BOM request.json under fb.ProfilePath + smartshuffle\\; version/id/op protocol; a single outstanding request; matching acknowledgement unlocks next request; unsent previews coalesce; cancellation removes unsent previews and waits behind the outstanding request. State polling is 200ms, invalid/incomplete JSON retains previous complete state. Missing acknowledgement surfaces an actionable component error after six seconds without overwriting the pending transaction.
- Startup now sends exactly one `state` handshake carrying `theme_version: '1.0.0'` and `theme_window: Number(window.ID)`. After all includes and app initialization succeed, the console records `Smart Shuffle Chinese Verdant 1.0.0 ready`. Native state can therefore confirm an actually loaded panel through CLI rather than relying on source installation alone.
- Added `views/preference.js`: shaded modal, actual native first eight preview tracks, square continuous coordinate grid and green ball, 150ms preview debounce, drag continuation outside grid, clamping, arrow steps .05, positive y upwards, Escape cancel, Enter apply only for a final nonempty token matching the current draft. Presets 均衡/常听优先/少听探索/回到中心. Apply remains open until native acknowledgement; stale_preview retains the dialog and requires a fresh apply. Native ui_open counter is consumed once; an acknowledged own-open cannot reopen a dialog already cancelled.
- Removed original JavaScript shuffle engine and its wrap-around callback, including playlist-copy mutation when removing rows. Native handles intelligent source play, play_id, next/previous, enable, restart and exact preview application. Sequential mode executes the source row directly; explicit native repeat-one remains available. Only `__smartshuffle__` is hidden from navigation; arbitrary handle sets retain the named `__verdant_np__` source.
- Queue uses native `queue` priority rows and actual committed `remaining` rows, with round and remaining count, and track IDs for clicking. Bottom bar has 随机偏好, 新一轮, scan counts, 暂停/继续 and failed scan 重试. Existing volume and fullscreen controls retained. No automatic ReplayGain scanner/tag writing was added; existing optional volume normalization still requires its explicit user action and confirmation. Discord presence defaults off.
- Added `data/output.js` and visible 音频输出 picker using documented fb.GetOutputDevices()/fb.SetOutputDevice(). Default nonexclusive devices are labeled WASAPI共享, `[exclusive]` and `[独占]` become WASAPI独占, actual device names and ASIO labels remain intact. Current output gets a radio mark. Opening/cancelling or selecting the current device does not switch output. Native IDs are used only after explicit selection of a different output. Malformed device JSON is rejected. Actual ASIO availability is exactly what foobar enumerates; the theme creates no drivers or device maps.

## Lyrics integration

Timed lyrics remain available and search beside audio first, followed by profile lyrics\\ filenames `artist - title.lrc`, `artist-title.lrc`, `title.lrc`, corresponding `.txt`, and `artist\\title.lrc`; filenames sanitize illegal Windows characters. Synced timestamps and unsynced scrolling are retained.

If a JSplitter child named **ESLyric** already exists, the theme calls `window.GetPanel('ESLyric')`, moves it to `(queue.x+10, queue.y+58, queue.w-20, queue.h-68, true)`, and shows it only on the lyrics tab. Geometry and visibility calls are cached to avoid repaint loops.

When the named child is missing, the theme requests the native SDK host through `lyrics_panel` with `{parent:Number(window.ID),x:queue.x+10,y:queue.y+58,w:queue.w-20,h:queue.h-68,visible:boolean}`. Unsent host updates coalesce and use the same acknowledged serialization as other operations. Native state must confirm `lyrics_panel.ready && lyrics_panel.visible` before the theme suppresses local timed lyrics. Modal/fullscreen/tab changes request hide; the ESLyric button explicitly retries host creation. Unload requests hide if alive, and native parent-window destruction remains the final safeguard if an outstanding transaction prevents dispatch before script teardown. If no native parent window ID is available, native View/ESLyric menu commands remain accessible. Real SDK host creation is implemented by the parent native task, not by this theme script.

These checks establish request/control behavior and syntax under Node mocks; they do not establish GDI text rendering or real foobar playback/device/ESLyric behavior. No foobar window or real output device was operated by this subtask. The user explicitly forbids Computer Use, so follow-up validation stays CLI/native-API only. Parent handles deployment and runtime state verification. CJK rendering, mouse feel, audible Lian II output and visible child-panel appearance remain unverified by this subtask.
